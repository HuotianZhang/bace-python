一致性审计：18 个状态，逐个扫

状态空间是三维的 —— 有没有面积（2）× 明暗读回来的是什么（3）× log 自动 / 强制开 / 强制关（3）。每个状态把 面板标签和全部脚注拿出来，扫里面的量纲记号（|J|、 mA cm⁻²、|I|、amps）， 只要出现了这张图没有在画的那个量，就记一次自相矛盾。 数字是这一页当场跑出来的。

脚注块占多少 px

量之前的想法是：D 最短，应该能省下几行。量完是空的 —— 四种写法在两个宽度上高度一模一样，因为那一句在 380 px 里 四种都还没到换行。所以 B / C / D 之间不是一场密度之争， 这一点和 rail-density.html 不同，得说清楚。 有差别的是离换行还剩多少：那一句真正占的宽，和卡给它的宽之间 还剩几个像素 —— 剩得越少，下一次改字、换字体、或者卡再窄一点， 就越容易多出一行。两张表都是加载后在浏览器里量的。

下一次怎么不再犯

上面四种写法里，B / C / D 都能把 #65 关掉 —— 但关掉的只是这一句。 notes() 还是一个可以自由造句的函数，下个月再加一条脚注， 照样可以写死一个量纲，而现有的 336 个测试一个都不会红。 所以真正的修法是两半：换掉这一句，再加一条把上面那张审计表 钉进测试的不变量 —— 面板标签和脚注里，不许出现这张图没在画的量。 下面是拿变异体验的：往 notes() 里塞回一个写死的量纲， 看测试抓不抓得住。
