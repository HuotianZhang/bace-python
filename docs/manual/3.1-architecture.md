# Architecture

The packages, what each owns, and the direction of every dependency.

## Layers

| Package | Owns | May import |
|---|---|---|
| `bace/core/` | The physics and the numerics: the scan axis, pulse levels, light − dark and the charge integral, the LED drive rules, per-shot diagnostics | Nothing of `bace` |
| `bace/drivers/` | One Protocol per instrument role (`protocols.py`), each with a real driver and a simulated one (`simulated.py`) | `core` |
| `bace/experiment/` | A run as a generator of typed events: `run_transient_scan`, `run_jv`; the `Rig` that holds the instruments | `core`, `drivers` |
| `bace/storage/` | Consumers of the event stream: the HDF5 file, the `.dat` files, folder names | `core`, `experiment` |
| `bace/bench/` | The staged check-out of a real bench (3.5) | everything below `service` |
| `bace/service/` | The process that owns the instruments: session, worker, catalogue, pipeline, journal, HTTP and WebSocket | everything above |
| `bace/params.py` | Parameter values with the layer each came from | Nothing of `bace` |
| `bace/config.py` | Loading and checking `rig.toml` and `run.toml` | `core`, `drivers`, `experiment`, `storage` |
| `bace/launcher.py` | Starting the service and opening the console | the standard library only |
| `ui/` | The console: ES modules served by the service, no build step | the service's HTTP and WebSocket routes |

`tests/test_architecture.py` enforces the directions: `core` imports no outer layer, the drivers do not import the experiment, the experiment and storage do not import the service, and only `service/app.py` and `service/__main__.py` import FastAPI and uvicorn. `pyvisa` is imported only when a real rig is built, so everything runs on the simulator without a VISA installation.

## One run, end to end

A manual run of the `bace` module, from Start to the files.

| Step | Where | What happens |
|---|---|---|
| 1 | `ui/lib/api.js` `startRun` | `POST /runs {module, params}` with the edited values |
| 2 | `service/app.py` | The route translates the body into one `Session` call and the session's exceptions into status codes |
| 3 | `service/session.py` `submit` | The catalogue resolves every parameter through its layers; `pipeline.validate` runs the check catalogue (4.2). A refusal is a 422 that lists every failed check. A manual run is a pipeline of one module node. |
| 4 | `service/journal.py` | `RunQueued` is written with the parameters chosen and the parameters resolved |
| 5 | `service/worker.py`, `session.py` | The run waits for the worker thread. When its turn comes the session reads the bench again and repeats the validation; a refusing verdict ends the run as `blocked`, otherwise it becomes the job that holds the instruments |
| 6 | `service/executor.py` `run_pipeline` | Walks the resolved schedule. For the module node it binds the temperature and the V_oc, announces the relay transition, and calls `Catalogue.build` |
| 7 | `service/modules.py` `_build_bace` | Returns a generator that, with `measure_dc`, measures J_sc, V_oc and J_sat under DC light; sets and settles the pulsed LED; moves the relay to the transient path; and runs `run_transient_scan` through `storage.recorder.record` |
| 8 | `experiment/transient.py` | Configures the chain, then for every shot sets levels, moves the shutter, acquires, processes, and yields `StepDone` with Q (3.2) |
| 9 | `storage/recorder.py` | Passes every event through and accumulates the completed shots. When the scan ends, by finishing, a stop or a failure, and at least one shot completed, it writes the `.dat` files and the HDF5 file |
| 10 | `service/worker.py`, `session.py`, `wire.py` | Each event crosses to the asyncio loop and is sent to every WebSocket client. A persistent event also receives a sequence number and is journaled; `StepPhase` and `JVPoint` are live-only frames |
| 11 | `ui/lib/store.js` | The console folds the frames into its state and redraws |
| 12 | `experiment/rig.py` `park` | After the last node, or on a stop or failure: bias and source-meter outputs off, shutter shut. `RunStateChanged("parked")` follows the terminal state. |

## The service

| Element | Rule |
|---|---|
| Process | One service per bench. The service binds its address and port before it opens an instrument, so a second service on the same port exits before it touches one; nothing prevents a service on another port from opening the same bench. |
| Worker | One thread owns every instrument. A run, a read-back and a bench action are each a job on it, one at a time: the bench lock. |
| Queue | A run submitted while another runs waits, first in first out; a queued run can be cancelled. |
| Observers | The power monitor and the temperature monitor read beside a run. The 1918-C is on USB, off the VISA bus; the 331 is read only while the worker's bus lock is free. |
| Stop | `after_shot` lets the current shot finish and keeps it; `abort` closes the generator at its next event. Both end parked. |
| Events | Every event is a typed dataclass (`experiment/events.py`). The session numbers each persistent event (`seq`), keeps the recent ones in a ring for reconnecting clients, and journals it. |
| Journal | One append-only JSON-lines file per session (3.3). The run list, the last-used values and the settle-time history are read from it. |
| Exit | Ctrl-C, or `POST /service/shutdown` from the console's `shut down`: the worker is aborted, the bench parked and the journal closed. |

The contract for every route and frame is `../service-contract.md`.

## Parameters and their layers

A parameter's value comes from the highest layer that holds one:

    default < run.toml < last used < edited < inherited < derived

| Layer | Holds |
|---|---|
| default | The parameter's default in its `ParamSpec`, taken from a configuration dataclass, `rig.toml` or the spec itself |
| run.toml | The recipe file |
| last used | The operator's choices in the most recent manual run of this module that ended `done` or `stopped`, from the journal; V_oc is not carried over |
| edited | What the operator typed in this session |
| inherited | A value a pipeline loop injects into its children, such as the LED level |
| derived | A value measured inside the pipeline, such as the V_oc of a preceding `jv_bace` node |

The console shows each value with its layer (`params.py` `ParamSet.resolve`). Inherited values come from pipeline loops; a derived V_oc can also come from the session for a manual `bace` run. A manual run journals its chosen and resolved values with `RunQueued`; the run file stores the settings it executed with (3.3).
