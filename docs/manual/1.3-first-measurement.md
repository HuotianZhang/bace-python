# A first measurement

The procedure for one BACE point at V_oc, from a cold start.

## Before starting

| Check | Why |
|---|---|
| The sample is mounted and contacted, and the cryostat is at the intended temperature | The service sets a setpoint but not the heater range or the PID (1.2). |
| All instruments are powered and the fibre reaches the sample | |
| Both ±15 V supplies read 15 V, and the amplifier leads were connected with the supplies off | The light and sample-holder amplifiers run from them; a lead connected live or reversed can destroy an amplifier (1.2). Each channel then draws about 0.04 A. |
| The I_d cable reaches CHAN2 through the 50 Ω feed-through, and the relay cable is connected red to red | Without the feed-through the current signal is not terminated; a reversed relay cable destroys the relay (1.2). |
| The pixel is B or E | The BACE holder contacts only these two. A small pixel shortens the RC time of the step (2.2). |
| The light is aligned on the pixel | At a low LED level in DC mode, move the spot to maximise the 2400's short-circuit current. |
| A light J–V over the LED levels to be used has been taken | It gives V_oc at each level and shows the range: from a little below 1 sun to about 2 suns is typical. |
| The LabVIEW program and every other bench tool are closed | One process may hold the instruments. A second one makes them answer the wrong queries. |

## Starting the service and the console

Double-click `BACE.pyw` in the repository root. A small window reports that the service is starting; the console opens in a window of its own once every instrument has been read, which takes from a few seconds to about a minute. If the service is already running, the console opens at once.

| To | Do |
|---|---|
| Close the console | Close its window. The service and any run in progress continue; `BACE.pyw` opens the console again. |
| End the service | Click `Shut down` at the right of the bar, then `Shut down?` within 6 s. Any run is aborted, the bench parked and the journal closed. |
| Read the service's output | `runs\logs\service_<date>_<time>.log`, one file per start. |
| Learn the console without instruments | `py -3 -m bace.launcher --sim`. Every instrument is simulated and nothing reaches the sample. |
| Ask the assistant | Click `Ask`. The panel opens beside the view and reads the bench, the runs and this manual; it changes nothing. `Settings` takes a provider, an address, a model and a key: Claude with an Anthropic key, or an OpenAI-compatible service such as the `Uni Potsdam · LLM Proxy` preset with a key from Account.UP. The key goes with each question and is not stored by the service. |

`scripts\Run Service.bat` starts the same service in a terminal, where Ctrl-C ends it; it is meant for diagnosis.

## Checking the bench

The service reads every instrument once at start. Two parts of the console report the result.

| Part | Where | What it shows |
|---|---|---|
| Rail | Top, every tab | One cell per instrument: Relay, Bias (81150A), SMU (2400), Shutter, LED (33220A), V_oc (the last one), Power, T. Hover a name for the instrument, a cell for detail. |
| Chain strip | Bottom, every tab | The four trigger-chain settings a BACE shot depends on, each with its expected value and a fix button. |

The four chain settings:

| Setting | Expected | If it is wrong |
|---|---|---|
| 33220A POL | INV | The Sync's rising edge would mean light on, and extraction would happen during illumination. With `external_trigger` on, as in `run.toml`, a BACE run writes the polarity itself before it pulses. |
| 81150A ARM | EXT | The bias step free-runs at a random phase of the LED cycle and still triggers the digitiser. |
| SLOP | POS | The 81150A arms on light on. |
| 81150A POL | as `output_polarity` requires | The device rests at the other level between pulses, and extraction happens on the other pulse edge. |

Click the fix button beside a setting to correct it. The 33220A polarity cannot change while its output is on: switch the LED off first (`led-off`), then fix the polarity.

## Naming the sample

The first chip in the bar names the sample. Click it and fill in Sample, Material and Pixel. These three, marked `folder`, form the start of every run folder's name, which the panel shows as the folder stem (3.3); without them a folder name begins with the temperature. Hover a field for what it records. The temperature is not typed here (3.3).

## V_oc

A BACE point at V_oc needs V_oc at the same LED level. The bace card's V_oc row says which value it will use and where it came from. Two ways to provide one:

| Way | How |
|---|---|
| `jv_bace` | Run the `jv_bace` card at the same `led_v`. Its V_oc is used by the next bace run. |
| `measure_dc` | Tick `measure_dc` on the bace card; the run measures V_oc with the 2400 before the shots. |

## One BACE point

On the bench tab, in the bace card:

| Field | Value for a first point | Meaning |
|---|---|---|
| Scan parameter (`axis_name`) | `vpre` | The swept quantity. |
| Scan range | start = stop = 0, Centre on V_oc on | One point, at V_oc. |
| V_coll (`vcoll`) | −1.0 V | The collection voltage at the device. |
| Delay (`delay_ns`) | 90 | Places the step about 3 ns after the light goes out (1.2). Light on for about 15 ns after the step needs about 72; check it with a photodiode first (2.2). |
| Loops (`n_loops`) | 10 | For independent loops of constant scatter the standard error falls as 1/√n_loops. |
| Hardware averages (`n_averages`) | 200 | Averages per trace. |

The card shows each parameter by its label; its code name, as in `run.toml`, is the first line of the tooltip and of the help line under the field (4.1). Every other parameter keeps the value shown; a value that was edited is marked as such. Click Scan. The service validates the run first and refuses it with the reason if a check fails.

The run monitor, under the rail, shows the loop and the shot in progress, the time left and the charge of each loop. Three controls end a run early:

| Control | Effect |
|---|---|
| Stop after shot | Finishes and keeps the shot in progress, then parks. |
| Abort | Ends the run at the next step boundary, discarding the shot in progress, then parks; asks for a second click (`Abort now?`). An instrument call already in progress completes first. |
| Cancel | Removes a queued run before it starts. |

## Ending

Every run ends parked, whether it finished, stopped or failed: the bias and source-meter outputs off and the shutter shut. The LED keeps running behind the shut shutter, so the next run need not wait for it to settle; switch it off with `led-off` at the end of the day. Park on the chain strip parks the bench at any time; while a run is active it aborts the run and asks for a second click.
