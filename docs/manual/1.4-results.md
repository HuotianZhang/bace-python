# Results

What a run reports, on screen and on disk, and how to decide whether a point is usable.

## The run summary

Each run ends with one line in the run list, for example:

    Q -0.190 ± 0.0041 nC (sem), 10 loops · 10/10

| Part | Meaning |
|---|---|
| −0.190 nC | Mean Q over the loops. The sign is that of the measured current after `current_sign` (4.4). |
| ± 0.0041 nC (sem) | Standard error of the mean: the standard deviation of the per-loop Q divided by √n. |
| 10 loops · 10/10 | Loops in the mean; shots completed of shots requested, fewer when the run was stopped. |

A run over several points reports the range of Q and the largest standard error instead.

## Traces

The bace card draws, for the newest shot, the light trace, the dark trace and their difference, with the integration window shaded. Reading them:

| Feature | Expected | If not |
|---|---|---|
| Before the trigger | Light and dark at the same level. The common level is the digitiser's zero offset and cancels in the difference. | An offset that differs between the two is drift or pickup (2.3). |
| The displacement spike | The same height and edge in both traces | It cancels in the difference only if both traces saw the same step. |
| Light − dark after the spike | A transient that decays to zero within the window | A difference that settles to a non-zero level means the baseline or the device state differs between the traces. |
| The traces' extremes | Inside the vertical range | Clipping: see below. |

## Checks on each shot

The service judges every shot and reports the verdict on the card and in the run record. A failed check does not remove the shot from the mean: the operator decides.

| Check | Fails when | Meaning |
|---|---|---|
| Rail | One trace holds a single extreme value for 7 or more consecutive samples | The digitiser clipped; the charge of the shot is meaningless. |
| Repeated extreme | An extreme value occurs more than 8 times | An averaged trace does not sit on one value; the range is probably too small. |
| Timing | The light and dark spikes are more than 0.25 ns apart and an edge is slower than 8 ns, or the Sync edges of the two traces are more than 0.1 ns apart | The trigger moved during the averaging or between the traces; the spike does not cancel. |
| Averages | The digitiser averaged fewer acquisitions than `n_averages` | The trace would be a partial average; the run stops with an error. |
| Empty trace | The digitiser returned no samples | Nothing to integrate. |

## Diagnostics in the file

Each shot also records quantities that show the state of the measurement chain:

| Field | Unit | Meaning |
|---|---|---|
| `pre_trigger_light_ua`, `pre_trigger_dark_ua` | µA | Mean current before the trigger in each trace: the baseline Q is referred to. |
| `late_offset_ua` | µA | Light − dark after the window minus light − dark before the trigger: what remains of the difference once extraction is over. |
| `dark_first` | | 1 when the dark trace was taken first in the shot (`alternate_order`). |

## A usable point

A point is usable when all of the following hold:

1. Light − dark returns to its pre-trigger level after the transient. `late_offset_ua` is the residue; its scatter on this bench is about ±3 µA per shot (`analysis/2026-10-26/scope-window/`). A residue well outside that, constant over the loops, disqualifies the point however plausible Q looks.
2. No shot failed a check.
3. The pre-trigger levels of the two traces agree within their scatter.
4. Q is stable over the loops: no trend from the first loop to the last.

## Files

Each BACE run writes one folder under `runs/`, named from the sample, the temperature, the LED level, V_oc, the baseline correction and the time, for example `s4_PTQ10_pxa_294K_1000mVLED_483mVVOC_offsetcorr_20261026_174743`. It holds an HDF5 file with the traces, every parameter and the bench configuration, and the legacy `.dat` files. A pipeline writes one parent folder with one folder per module run. The format is described in 3.3.

The results tab lists every run of the session and earlier ones, and draws Q against LED level and temperature for pipelines. Selecting a cell or a node opens its numbers and three sections: Flags (the observations on that node, kept with the record rather than the folder), Files (the node's folder: the HDF5 file with `/metadata`, the `.dat` files and every trace it kept, as above) and Provenance (which layer each parameter came from; a run read back from the journal has its values but not their layers). `Run bace again` queues one manual run with the node's overrides, at the bench's present V_oc and temperature: a manual run has no loop to bind them.
