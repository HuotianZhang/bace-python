**6.0 % apart on the peak, 2.8 % on τ, 4.0 % on Q, and both spikes land at 328
ns of record time.** Tests: 212 passed / 7 skipped.

The "the port is 3× low against LabVIEW" that took two evenings started with
taking the 23:16 LabVIEW run as the baseline. LabVIEW **itself**, run at 23:16
and again at 02:16 with not one parameter changed, fell from τ 190 ns to 71 ns
and from Q −9.2e−10 to −3.3e−10. **The reference was drifting.**

The last row is not a failure but a road that is closed: `--as-found` wanted to
"write not one level and inherit the bench exactly as it stands", but the VI
lights every point before darkening it, and finishes on the **dark** levels
(`HIGH 0.505434 / LOW 0`, i.e. v_pre = 0). The device is held shorted while
lit, and stores no charge. To inherit the bench, use `bare.py --vpre …` without
`--as-found`.

## Settled (with evidence, no longer inferred from a manual)

- **The criterion**: light minus dark **must return to zero in the steady
  state**. Not "where V_oc landed". Of the four polarity combinations only ④
  (a pure negation) has normal dynamics; that ② sits at 4.45 mA in the steady
  state is exactly what says it is wrong.
- **The polarity algebra** (verified numerically): `output_polarity`
  (`:OUTP1:POL`) = a pure swap of (baseline, pulse); `invert_polarity` = swap
  and negate; the two together = a pure negation. This does not depend on the
  NORM/INV label, which does not match the data.
- **The amplifier is inverting, gain 4, zero offset**: the generator's
  `:VOLT1:LOW` → v_pre, `:VOLT1:HIGH` → v_coll. The `(0.505434, 0)` read back
  at 02:20 agrees bit for bit with the dark shape `(span/4, 0)` that
  `pulse_levels(invert=True)` produces.
- **`trigger_offset_s = 0`**: at the same `Delay(ns)=90`, both sides put the
  displacement spike at 328 ns. The earlier 47 ns was measured down a different
  path.
- **`timebase_ns_per_div = 200`**: on the panel, Timebase 200 ns and Pulse
  Width 5e3 ns are written side by side and are unrelated. 200 also puts t0 on
  the panel's 320 ns (trigger 200 + 120).
- **The LED really is dark at 0.4 V**: measured with the power meter, the low
  level puts out 0.009 % of the conducting level. The "the light never actually
  goes off" suspicion is ruled out. The working intensity is 20.7 µW.
- **Current = voltage / 5.192, divided exactly once, in `Infiniium._fetch`.**
  `_fetch_volts` deliberately does not divide (auto-range works in the voltage
  domain); probe attenuation is left to the instrument's
  `:CHAN:PROB:EXT:GAIN` and is not multiplied again in software.
- **`:DIGitize` + `*OPC?` writes no setting**, and returns one complete
  averaged record; `acquire()` on the other hand must restart the averager, or
  the light trace mixes in the dark one before it.
- **Dark = the same span, translated to start from 0**
  (`dark_reference = "translated"`): light −1.01354 → +1.00000 V, dark 0 →
  +2.01354 V. The same span, a different absolute interval.

## Fixed

- **A file now records the convention actually run, not only the one asked
  for**: `events.py` gains `InstrumentState`; the HDF5 gains
  `/config/resolved`, and the schema rises to `bace-run/2`. This started with
  `output_polarity = "leave"`, which by design writes nothing — leaving the
  file unable to say whether it was measured under NORM or INV.
- **`offset_correct` subtracts the signal away when the tail is not the
  baseline**: added `core.process.baseline_is_flat()`, which compares the head
  and the tail of the record and warns when it is not flat, **changing no
  number**. The round that prompted it gave Q = −3.0e−10 — an entirely
  presentable and entirely wrong figure.
- **Dark had no settle time at all**: `dark_settle_s` used to sleep **before**
  the shutter shut, so acquisition began the moment it closed, while light had
  `settle_s`. Added `shutter_settle_s`, which applies after the shutter moves
  on both branches.
- **Two bugs in the 1918-C power meter**: the body key for `/api/units` was
  written as `units` (the console reads `code`); and `HTTPError` was swallowed
  by the `URLError` branch (the former is a subclass of the latter), reporting
  "cannot connect" instead of "refused, 400". Separately, `rig.power` was
  always `None` in `tools/scan.py`, so `intensity` was never recorded.

New tools: `tools/bare.py` (reads about 60 instrument states back into
`0_instrument_state` at the start of every round, writing not one of them, then
moves only the levels and the shutter) and `tools/lightpower.py`.
New recipes: `run-labview.toml`, `run-labview-same.toml`, `run-bace.toml` and
`run-lightcheck.toml`, each with a `.bat`.
