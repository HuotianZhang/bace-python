Design

BACE Software Architecture

One program, four layers, and a short list of places you touch when something changes. Designed so a new instrument, a new axis or a new output is an addition rather than an edit.

Four principles

Every structural decision below follows from one of these. Where two pull against each other, the earlier one wins.

  1. Dependencies point inward, and the centre is pure. core/ knows physics and nothing else — no VISA, no files, no sockets. It is the part that is already validated against your data, and it stays testable without a rig forever.
  2. Modular does not mean many programs. One package, one service, one UI. The modules are seams inside it, not separate tools to maintain. A seam earns its place by being somewhere change actually arrives.
  3. Swap by substitution, not by editing. Anything that might be replaced — an instrument, a storage format, a transport — sits behind a small contract with at least two implementations, one of which is a simulator. If there is only ever one implementation, it does not need a contract.
  4. One event stream, many listeners. The experiment says what happened; storage, the UI, the legacy writer and the log all listen. Adding a consumer never touches the experiment.

The one rule that keeps this honest

core/ may not import from drivers/, experiment/, storage/ or service/. A three-line test asserts it. That single constraint is what guarantees the validated numerics stay validated — and what lets the whole physics layer run against your 2026-08-07 archive on any machine, with no instruments and no LabVIEW.

The contracts

Six roles, each a Protocol. A driver satisfies one by having the right methods — no base classes, no registration, no inheritance to fight later.

class BiasSource(Protocol):        # 81150A, or whatever replaces it
    def set_levels(high_v, low_v, *, delay_s, width_s) -> None: ...
    def enable_output(on: bool = True) -> None: ...
    def disable_output() -> None: ...
    output_enabled: bool               # the router reads this before switching

class Digitizer(Protocol):          # Infiniium
    def acquire(n_averages, *, autorange_first: bool) -> Trace: ...
    def configure_timebase(ns_per_div, record_length) -> None: ...

class SourceMeter(Protocol):         # Keithley 2400
    def measure_voc() -> float: ...
    def measure_jsc() -> float: ...
    def sweep(start_v, end_v, step_v, **kw) -> tuple[array, array]: ...
    output_enabled: bool

class Shutter(Protocol):
    def unblock() -> None: ...
    def shut() -> None: ...
    def dark() -> ContextManager: ...

class Router(Protocol):             # the relay
    def dc() -> ContextManager: ...
    def transient() -> ContextManager: ...

class PowerMeter(Protocol):         # Ophir yesterday, Newport 1918-C today
    def read() -> float: ...

Two implementations exist for each from day one: the real driver and a simulated one. That is not test scaffolding — it is how the experiment layer gets built and debugged before the drivers are trusted, and how you reproduce a fault later without occupying the bench.

The axis, as a parameter

The original computed Vcoll1Loop and Delay1Loop as per-step arrays and then filled both with a constant. Making the axis data rather than code is finishing that, not adding to it.

from dataclasses import dataclass

@dataclass(frozen=True)
class Axis:
    name: Literal["vpre", "delay_ns", "vcoll"]
    start: float
    stop: float
    step: float
    centre_on_voc: bool = False   # vpre only: start/stop are offsets from Voc

# the three experiments, as three values rather than three code paths
BACE      = Axis("vpre",     -0.001, +0.001, 0.001, centre_on_voc=True)
BACE_wide = Axis("vpre",       0.0,    1.0,   0.02)
TDCF      = Axis("delay_ns",  10.0, 1000.0,  10.0)
FIELD     = Axis("vcoll",     -4.0,   -0.5,   0.25)

The sequencer builds the grid; pulses.py reads whichever of the three is varying and holds the other two at their pinned values. Nothing in the acquisition path knows which axis it is on.

Where repeats come from

Loops, not the axis. That makes "Q at Voc" an axis of zero width with N loops — no curvature bias, no special case, and the same code path as a 50-point sweep. It also means the three-points-around-Voc convention becomes a choice you make in run.toml rather than a shape baked into the program.

Extension points

The test of a modular design is what you have to touch. For each likely change:

Nothing in that table requires editing core/ or the experiment generator. That is the whole point of the layering, and it is worth checking any future change against this table — if a change forces an edit in two layers, the seam is in the wrong place.

One correction to the control structure

The plan above called the experiment an async generator. Building it showed that is wrong, for a concrete reason.

Every call inside the run loop is blocking VISA I/O, and VISA sessions are not thread-safe, so the loop has to run on the one thread that owns the instruments. An async def generator whose body blocks for two seconds while a scope averages would stall the service's event loop for two seconds — every other client, every heartbeat, every abort request, waiting on an oscilloscope.

So the run is a synchronous generator executed on the instrument thread, and service/ adapts it to async at its own edge by pumping events into an asyncio queue. Nothing else about the design changes: it still yields typed events, still has many listeners, and abort still works two ways — a consumer that stops iterating raises GeneratorExit at the yield and the finally parks the bias, or a consumer that wants a reported stop passes an abort callable polled once per step. Async belongs where the waiting is on sockets, not where it is on an oscilloscope.

Build order

Each step leaves something runnable, and nothing waits on the bench that does not have to.

  1. core/axis.py and the protocols. Done. Small, pure, and they fix the shape everything else fits. All four real drivers and all six simulated ones satisfy their contracts, and a three-line test asserts core/ never reaches outward.
  2. drivers/simulated.py and experiment/transient.py. Done. The standalone measurement runs end to end against simulated instruments; abort, walk-away and a mid-run instrument failure all unwind to a parked bias and a closed shutter. Thirty tests pass, the archive regression among them.
  3. storage/. Both writers, verified by round-tripping your 7 August archive: read it, write it, diff it.
  4. The remaining real drivers. Smoke test each against its instrument alone, then substitute them for the simulated ones one at a time.
  5. experiment/intensity_series.py. The wrapper — SourceMeter, LED sweep, relay. Last, because it is the only part where a mistake reaches the sample.
  6. service/ and ui/.
