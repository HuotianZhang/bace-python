Control and data flow

BACE Instrument Chain

What is wired to what, which commands belong at which level of the run, and the one place where the software is deliberately not in the loop.

1 · The chain

Five instruments, two of them behind vendor DLLs rather than VISA. The thing to read off this picture is the trigger chain: the LED generator is the master clock, the bias generator is armed from it, and the whole fast loop closes in hardware without the host.

The two DIO lines — resolved

Both boxes are Deditec modules on ID 9, channel 0. Which is which follows from two independent places in the code.

Module 0 is the shutter. shutter_lv2012.vi hard-codes its own target — module nr 0, ID 9, channel 0, with a 0.1 s settling wait — and its only input is a boolean. TDCF-BACE.vi, the standalone measurement that has a shutter and no relay, calls that VI and touches nothing else on the DIO.

Module 1 is the relay, and 1 means Keithley. Tracing every Dapi DO Set1 by event frame: both frames set module 1 high on entry and then use the SourceMeter. The J-V frame never lowers it — the Keithley stays connected for the whole sweep. The BACE frame lowers it exactly once, immediately after measJsc,Voc and before the engine runs the transients. That is the only moment in the program where the bias path changes.

BACE frame
   module 0 ← 1      shutter open
   module 1 ← 1      relay → Keithley
   Enable Output → measJsc,Voc → Enable Output off
   module 1 ← 0      relay → amplifier
   engine runs, toggling module 0 for each light/dark pair

Worth knowing: the un-driven state leaves the device on the amplifier, so the rig powers up on the transient path — safe while the 81150A output is off, but not the fail-safe direction you might assume.

Still open: the power meter's optical position — a split fraction of the beam, or swapped into the sample position for calibration? It decides whether intensity can be logged during a run or only before one.

Two consequences for the code

  • The driver objects are stateful on purpose. Each holds what it has already been told, so a session-level command issued in the inner loop is a no-op rather than a VISA round trip. That is the difference between a five-minute run and a fifteen-minute one.
  • The relay belongs to a router, not to the experiment code. It moves only when both sources report their outputs disabled, and it is not thrown back after every block — a mechanical relay has a finite operation count, and safety comes from the outputs being off rather than from the position. That turns 600 needless throws per run into three.
  • One number is used twice and must not drift. The DC level for the Voc measurement and the pulse high level for the transient are the same drive; the prebias axis is only centred correctly while they agree. core/illumination.py asserts it rather than trusting the call order.
  • The unwind path is not the reverse of setup. On abort the only things that matter are: 81150A output off, shutter closed, Keithley output off, device at 0 V. Everything else can be left as it is. Writing that as one finally rather than an unwound stack keeps it correct when the failure happens halfway through configuration.
