The reference itself was drifting

Put the port beside a LabVIEW run from eight minutes earlier and they differ by 6% on the peak, 3% on the decay time and 4% on the charge. That earlier 4× gap was not the program being wrong — it was the device changing over the three hours from 23:16 to 02:16: LabVIEW’s own τ fell from 190 ns to 71 ns, and its own Q from −9.2×10⁻¹⁰ to −3.3×10⁻¹⁰ C.

three · why that round kept only an eighth

--as-found inherited the dark levels

The 02:20 round wrote nothing and used the levels LabVIEW had left in the generator: :VOLT1:HIGH 0.505434, :VOLT1:LOW 0. That is exactly the dark pair — the span 4 × 0.505434 = 2.0217 V matches, but the baseline is 0, i.e. v_pre = 0. The device is held shorted while lit and stores no charge to begin with, so only 4.5×10⁻¹¹ C came out.

this road is closed

--as-found was meant to write not one level and inherit the bench entirely, but what the VI leaves behind is the dark levels, so the bias it inherits is wrong. To inherit the bench, the only way is bare.py --vpre … without --as-found: timebase, trigger, delay, averaging, LED and relay are all inherited as they stand, and only that one pair of levels is recomputed from v_pre — which is how the 02:08 round was run, and it agreed.

It also settled something that had never had evidence: the polarity mapping. The dark shape pulse_levels(invert=True) produces is (span/4, 0), agreeing bit for bit with the (0.505434, 0) read back; light should be (+0.2500, −0.2559). That nails down “LOW → v_pre, HIGH → v_coll”, which is no longer inferred from a manual.

four · what is left

Only a global sign

The port is all positive and LabVIEW all negative, with the same shape and the same size. This is not a difference in physics but a sign convention.

  • Add current_sign = -1 to rig.toml and multiply once in the driver’s fetch layer. Stop reaching for the generator’s polarity switch to fix it — that switch changes the voltage the device actually sees, while the sign changes only which way the trace is drawn; the two must not be confused.
  • The device drifts. A LabVIEW run used as a reference has to be an adjacent one; data a few hours old cannot be a baseline, and that is exactly what cost two evenings here.
  • Record 0_instrument_state every round (the 02:20 round already does). Seeing at a glance that the dark levels had been inherited is entirely down to it.
