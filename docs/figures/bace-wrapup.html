one · the evidence

That earlier 4× gap was the device drifting

The “the port is 3× low against LabVIEW” that took two evenings started with taking the 23:16 LabVIEW data as the baseline. But LabVIEW itself, run at 23:16 and again at 02:16 with not one parameter changed, fell from τ 190 ns to 71 ns and from Q −9.2×10⁻¹⁰ to −3.3×10⁻¹⁰ C. The reference was moving.

two · settled

These have evidence now, and are no longer inferred from a manual

criterionLight minus dark must return to zero in the steady stateNot “where V_oc landed”. Of the four polarity combinations only ④ (a pure negation) has normal dynamics; that ② sits at 4.45 mA in the steady state is exactly what says it is wrong.
polarityThe polarity algebra (verified numerically)output_polarity(:OUTP1:POL) = a pure swap of (baseline, pulse); invert_polarity = swap and negate; the two together = a pure negation. It does not depend on the NORM/INV label, which does not match.
wiringThe amplifier is inverting, gain 4, zero offsetThe generator’s :VOLT1:LOW → v_pre, :VOLT1:HIGH → v_coll. The (0.505434, 0) read back at 02:20 agrees bit for bit with the dark shape (span/4, 0) that pulse_levels(invert=True) produces.
timingtrigger_offset_s = 0At the same Delay(ns)=90, LabVIEW and the port both put the displacement spike at 328 ns of record time. The earlier 47 ns was measured down a different path.
samplingtimebase_ns_per_div = 200On the panel, Timebase 200 ns and Pulse Width 5e3 ns are written side by side and are unrelated. 200 also puts t0 on the panel’s 320 ns (trigger 200 + 120).
lightThe LED really is dark at 0.4 VMeasured with the power meter: the low level puts out 0.009 % of the conducting level. The “the light never actually goes off” suspicion is ruled out. The working intensity is 20.7 µW.
unitsCurrent = voltage / 5.192, divided exactly once, in Infiniium._fetch_fetch_volts deliberately does not divide (auto-range works in the voltage domain); probe attenuation is left to the instrument’s :CHAN:PROB:EXT:GAIN and is not multiplied again in software.
acquisition:DIGitize + *OPC? writes no settingIt returns one complete averaged record; acquire() on the other hand must restart the averager, or the light trace mixes in the dark one before it.
principleDark is the same span, translated to start from 0dark_reference = "translated": light −1.01354 → +1.00000 V, dark 0 → +2.01354 V. The same span, a different absolute interval. This is what BACE ought to do, and it is the convention rebuilt from the VI.

three · fixed

What this round changed

recordA file now records the convention actually run, not only the one asked forevents.py gains InstrumentState; the HDF5 gains /config/resolved and the schema rises to bace-run/2. What prompted it: output_polarity = "leave" by design writes nothing, leaving the file unable to say whether it was measured under NORM or INV.
trapoffset_correct subtracts the signal away when the tail is not the baselineAdded core.process.baseline_is_flat(), which compares the head and the tail of the record and warns when it is not flat — changing no number. The round that prompted it gave Q = −3.0e−10, an entirely presentable and entirely wrong figure.
timingDark had no settle time at alldark_settle_s used to sleep before the shutter shut, so acquisition began the moment it closed, while light had settle_s. Added shutter_settle_s, which applies after the shutter moves on both branches.
power meterTwo bugs in the 1918-C, and it was never attachedThe body key for /api/units was written as units (the console reads code); HTTPError was swallowed by the URLError branch, reporting “cannot connect” instead of “refused, 400”. And rig.power was always None in tools/scan.py, so intensity was never recorded.

New tools: tools/bare.py (reads about 60 instrument states back into 0_instrument_state at the start of every round, writing not one of them, then moves only the levels and the shutter) and tools/lightpower.py (logs the optical power of the LED, lit and dark, continuously); recipes run-labview.toml / run-labview-same.toml / run-bace.toml / run-lightcheck.toml, each with a .bat.

four · open

Where the next round picks up

firstAdd current_sign = -1 to rig.tomlMultiplied in Infiniium._fetch, and carried into the protocol and the simulator alike. The port is all positive and LabVIEW all negative, with corr(−bare, lv) = 0.9988 on the dark trace — a sign convention, not physics. Stop reaching for the generator’s polarity switch to fix it.
disciplineA LabVIEW run used as a reference has to be an adjacent oneA device can drift 2.8× in three hours. Data from the night before cannot be a baseline — that is exactly what cost two evenings here.
hardcodedThe relay and shutter constants are still written into the coderouting.py’s TO_AMPLIFIER/TO_SOURCEMETER and shutter.py’s OPEN/CLOSED → rig.toml. Wiring polarity is not fixed, and does not belong nailed into the foundations.
triggerconfigure_trigger is not in the BiasSource protocol yetAs it stands: tools/scan.py sets it, the run path itself does not.
syncD:\BACE\bace-python has never been syncedThese sessions only ever attached Q:. Next time D: is attached, mirror the other way per bace-paths.md. Two pieces of litter are also left in the repository root, _xfer.txt and _to_delete/, which this end has no permission to delete.

Further out: parameter provenance made visible (hardcoded argparse defaults → read run.toml), a max_bias_v ceiling, one vocabulary for events, splitting checks.py. The full list is in claude/bace-open-defects.md.
